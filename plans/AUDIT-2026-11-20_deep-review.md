## BLOCKER / CRITICAL Findings

### C1. `memory_add` -> `reflect()` Vertical Scope Escalation (`scope="agent"` -> `scope="space"`) & Confidence/Provenance Forgery

- **Locations:** `src/engramory/access/surface.py:515-520`, `src/engramory/workers/distillation.py:126-129`, `src/engramory/workers/distillation.py:154-160`, `src/engramory/workers/distillation.py:176-243`, `src/engramory/core/repository.py:553`
- **Symbols:** `AccessSurface.memory_add`, `reflect`, `_build_episode_provenance`, `_resolve_episode_confidence`, `Repository.offboard_agent_space`
- **Failure scenario:** `memory_add` authorizes `TargetScope(tenant_id=ctx.tenant_id, scope=scope)` (`surface.py:515`), then initializes `merged_meta = dict(metadata)` and only overwrites `merged_meta["scope"]` inside `if scope != "agent":` (`surface.py:518-519`).
  - A low-privileged caller holding only `scopes=frozenset({"agent"})` calling `memory_add(ctx, content="...", scope="agent", metadata={"scope": "space", "effectiveness_score": 1.0, "producer": "platform-admin"})` passes `_decide(..., scope="agent")` while persisting `"scope": "space"` into `episodes.metadata`.
  - When `reflect()` runs (`distillation.py:126-129, 159`), it reads `episode.metadata["scope"] == "space"` and promotes the distilled L2 `Memory` directly into tenant-wide `scope="space"`, bypassing ADR-07 scope checks, `memory_promote`, and ADR-06 `evidence_ref`.
  - Simultaneously, `_resolve_episode_confidence` (`distillation.py:233-243`) accepts forged `metadata["effectiveness_score"] = 1.0`, `_build_episode_provenance` (`distillation.py:176-230`) copies forged `producer`/`origin`/`agent_type` verbatim into L2 `provenance`, and `offboard_agent_space` (`repository.py:553`: `coalesce(metadata->>'scope', 'agent') = 'agent'`) fails to purge the escalated episode on agent offboarding.
- **Root cause:** `memory_add` fails to unconditionally pin `merged_meta["scope"] = scope` and accepts reserved confidence/provenance metadata keys from untrusted callers.
- **Fix:** Unconditionally assign `merged_meta["scope"] = scope` in `AccessSurface.memory_add`, and strip or reject caller-supplied reserved provenance/confidence keys (`effectiveness_score`, `producer`, `origin`, `agent_type`, `calibration_delta`) on raw `memory_add` calls.

### C2. Cross-Scope / Cross-Agent Memory Takeover (`memory_forget`), Feedback IDOR & Roster Domain Leak

- **Locations:** `src/engramory/access/surface.py:563-586`, `src/engramory/access/surface.py:687-709`, `src/engramory/core/repository.py:263-345`, `docs/sdd/06_SPEC/SPEC-04_distillation_engine.yaml:80`
- **Symbols:** `AccessSurface.memory_forget`, `Repository.retire_memory`, `AccessSurface.memory_feedback`, `Repository.record_feedback`, `AccessSurface.agent_roster_list`
- **Failure scenarios:**
  - **Cross-scope deletion (`memory_forget`):** Authorizes only `scope="agent"`, then calls `retire_memory(memory_id, tenant_id=ctx.tenant_id)` which updates `WHERE id = %(id)s AND tenant_id = %(tenant_id)s AND valid_to IS NULL` with zero check on `agent_id`, `project_id`, `domain_id`, or `memory.scope in ctx.scopes`. Any `scope="agent"` caller can permanently retire another agent's private memories or tenant-wide `project`/`domain`/`space` institutional memory.
  - **Cross-agent feedback IDOR, shared quarantine & confidence toggle drift (`memory_feedback`):** `record_feedback` queries `memory_retrievals WHERE id = %(id)s AND tenant_id = %(tenant_id)s` with zero check on `memory_retrievals.agent_id = ctx.agent_id` (IDOR). Any agent retrieving or guessing a `retrieval_id` can mark `"harmful"`, which immediately sets `status = 'quarantined'` across shared `space`/`domain`/`project` memories (explicitly required by `SPEC-04:80` / `@ears: EARS.01.03.b800`), hiding institutional memory tenant-wide. Furthermore, toggling `useful` (`+0.05`) `<->` `not_useful` (`-0.10`) on the same `retrieval_id` bypasses `prev["feedback"] == outcome` without reversing prior deltas, driving confidence toward `0.0`.
  - **Cross-department roster leak (`agent_roster_list`):** Authorizes `req_scope = "project" if "project" in ctx.scopes else "agent"` (`surface.py:698`) without calling `_enforce_domain_boundary` for domain-bound non-`space` callers, letting a domain-bound agent inspect profiles, `standing_preferences`, `brain_config`, and skill counts of other departments.
- **Root cause:** Action-level authorization omits target row ownership/scope/domain checks, feedback applies additive deltas without write-once/reversal semantics, and `SPEC-04` mandates single-vote immediate quarantine even on shared scopes.
- **Fix:** Fetch target memory/retrieval ownership first and enforce `scope in ctx.scopes`, `agent_id == ctx.agent_id`, `project_id`, and `domain_id` boundaries; make feedback write-once or delta-reversing; enforce `_enforce_domain_boundary` on `agent_roster_list` for non-`space` callers; author an `SDD2C` amendment to `SPEC-04:80` / `EARS.01.03.b800` / `TDD-04` before gating shared-scope `harmful` quarantine behind multi-signal thresholds or elevated scopes.

### C3. Tenant-Wide Graph Disclosure for `scope="domain"` Callers (`eff_project_id = None`) & Recursive Hop Leaks

- **Locations:** `src/engramory/access/surface.py:397`, `src/engramory/access/surface.py:419`, `src/engramory/access/surface.py:478`, `src/engramory/access/surface.py:1961`, `src/engramory/core/repository.py:1896-2157`, `src/engramory/adapters/dev/graph_neo4j.py:220-352`
- **Symbols:** `AccessSurface.graph_neighbors`, `AccessSurface.context_slice`, `AccessSurface.blast_radius`, `AccessSurface.knowledge_search`, `Repository.{find_neighbors,find_ancestors,find_descendants}`, `Neo4jGraphAdapter.{neighbors,ancestors,descendants}`
- **Failure scenarios:**
  - **All project/domain graph isolation disabled on `scope="domain"`:** All 4 `AccessSurface` graph methods compute `eff_project_id = ctx.project_id if scope in ("agent", "project") else None`. Because `jwt_auth.py:222` automatically grants `"domain"` scope to every domain-bound actor and neither Postgres nor Neo4j filters graph traversals by `domain_id`, calling any of the 4 tools with `scope="domain"` passes `project_id=None` and exposes every project's private SDD, KB, and media graph entities across the entire tenant.
  - **Unfiltered `project_id IS NULL`, missing edge checks & intermediate-hop bridging:** Even when `project_id` is non-null, all 3 Postgres CTEs and all 3 Neo4j traversals match `project_id IS NULL` nodes (leaking `domain`/`space` nodes to `project`-only callers), `find_ancestors`/`find_descendants` and all 3 Neo4j queries omit edge `r.project_id` checks, and `find_neighbors`'s recursive arm (`repository.py:1942-1954`) checks `mid_e` but never filters target hop nodes by `project_id` (allowing `depth >= 2` walks to bridge through foreign-project nodes). Separately, `repository.py:1981-1991, 2064-2074, 2147-2157` spread `**row["properties"]` after `"name"` and `"tenant_id"`, allowing stored property keys to spoof identity fields in returned dicts.
- **Root cause:** `eff_project_id` drops project confinement for `scope="domain"` without substituting `domain_id` or `scope` filtering, and recursive CTE/Cypher traversals omit edge/hop boundary predicates.
- **Fix:** Propagate and enforce `domain_id` and `allowed_scopes` (or require `eff_project_id = ctx.project_id` for non-`space` scopes) across all 4 `AccessSurface` graph methods, Postgres CTEs, and Neo4j queries; filter edges and every recursive hop node by project/domain/scope; stop returning `project_id IS NULL` nodes to `project`-only callers; unpack `**row["properties"]` before fixed identity keys.

### C4. Cross-Scope Ownership Hijacking (`project_id IS NULL`), Same-Project Overwrite of `space`/`domain` Docs & `step_uid` Collision

- **Locations:** `db/migrations/0008_runbooks_and_doc_governance.sql:61`, `src/engramory/core/repository.py:928-940`, `src/engramory/core/repository.py:1047-1067`, `src/engramory/core/repository.py:1544-1660`, `src/engramory/core/repository.py:2216-2326`, `src/engramory/access/surface.py:1784`, `src/engramory/access/surface.py:2205-2345`
- **Symbols:** `kb_runbook_steps`, `Repository.upsert_kb_section{,s_batch}`, `Repository.upsert_kb_document`, `Repository.upsert_kb_runbook_steps`, `Repository.{upsert,bulk_upsert}_graph_{entity,entities,relation,relations}`, `AccessSurface.docs_ingest_runbook`
- **Failure scenarios:**
  - **`project_id IS NULL` ownership hijack across 7 Postgres upserts:** `upsert_kb_section`, `upsert_kb_sections_batch`, `upsert_kb_document`, `upsert_graph_entity`, `upsert_graph_relation`, `bulk_upsert_graph_entities`, and `bulk_upsert_graph_relations` all permit `ON CONFLICT DO UPDATE` whenever `<table>.project_id IS NULL` and execute `project_id = COALESCE(EXCLUDED.project_id, <table>.project_id)`. Any low-privileged `project`-scoped caller can overwrite tenant-wide (`space`) or `domain` rows stored with `project_id=NULL`, reassigning row ownership to the caller's `project_id`. (`upsert_graph_entity` also lacks `RETURNING`/rowcount checks and silently ignores collisions.)
  - **Same-project scope/domain overwrite:** None of `upsert_kb_section`, `upsert_kb_sections_batch`, or `upsert_kb_document` check existing `scope` or `domain_id`. Because `AccessSurface.knowledge_ingest` (`surface.py:1784`) and `docs_ingest_runbook` (`surface.py:2321`) stamp `project_id=ctx.project_id` even on `space`/`domain` writes — and `jwt_auth.py:206` defaults `project_id="core"` for callers without `projects` — any `scope="project"` caller in `"core"` can overwrite a `space`-admin's document (cascade-replacing runbook steps) or another department's `domain`-scoped docs.
  - **`kb_runbook_steps` `step_uid` hijack:** `kb_runbook_steps` has `PRIMARY KEY (tenant_id, step_uid)` (`0008:61`) without `doc_id`, `docs_ingest_runbook` accepts caller-supplied `st.step_uid`, and `upsert_kb_runbook_steps` updates `command_body`/`tier`/`mode` on conflict without checking `doc_id`. Direct Python `AccessSurface.docs_ingest_runbook` callers can overwrite another project's executable runbook step in place; over MCP/CLI, `parse_markdown_document` builds `f"{doc_id}#{step_id}"` after `upsert_kb_document`, so MCP/CLI exploitation requires `#` in `doc_id` or `step_id`.
- **Root cause:** Conflict predicates check only `project_id IS NULL OR project_id = EXCLUDED.project_id` without checking `scope`/`domain_id` ownership, and `kb_runbook_steps` keys conflict targets without `doc_id`.
- **Fix:** Tighten all 7 upsert conflict predicates so existing `space`/`domain` or cross-project rows cannot be claimed or overwritten by lower-scoped callers, and verify rowcount/`RETURNING` on `upsert_graph_entity`. Atomically migrate `kb_runbook_steps` PK to `(tenant_id, doc_id, step_uid)` AND update `ON CONFLICT (tenant_id, doc_id, step_uid)` (preventing Postgres `42P10`), plus reject `#` inside `doc_id`/`step_id` and bind `step_uid == f"{doc.doc_id}#{step.step_id}"`.

  - **Scope escalation on default `scope=None`:** `knowledge_search(ctx, "q")` authorizes `eff_scope="project"`, then passes `scope=None` to `search_kb_sections` (`surface.py:1952`), disabling SQL scope filtering and returning `space` rows plus `agent` and other-department `domain` rows that share `project_id == ctx.project_id`.
  - **Unconditional `space` & same-project leaks:** `search_kb_sections` and `slice_runbook` unconditionally return `scope = 'space'` rows even when `'space' not in ctx.scopes`; their `OR project_id = %(project_id)s` branches omit `AND scope = 'project'`, leaking `agent` and other departments' `domain` rows sharing `project_id`. `kb_sections` (`0003:90-105`) has no `agent_id` column despite `KBSection` allowing `scope='agent'`.

### C6. Arbitrary Host Command Execution & Dead Safety Guard in `smoke_run_green_steps`

- **Locations:** `src/engramory/core/docs_tools.py:228-311`, `src/engramory/core/docs_tools.py:865-884`, `src/engramory/core/docs_tools.py:1439-1526`
- **Symbols:** `_GREEN_BANNED_PATTERNS`, `check_green_step_safety`, `parse_markdown_document`, `smoke_run_green_steps`
- **Failure scenarios:**
  - **Trivial regex-denylist bypasses to host RCE (`bash -c` without gVisor):** Redirection lookbehind `(?<![0-9>&])>>?` (`docs_tools.py:295`) allows `echo payload 1> ~/.bashrc`, `2> file`, and `&> file`. Heredocs/here-strings (`python3 <<'EOF' ... EOF`, `bash <<< '...'`) and shell quoting (`r''m`, `r\m`, `$'\x72\x6d'`) bypass `\b...\b` rules. Unlisted mutating tools (`cp`, `ln`, `tar -xf`, `wget -O`, `git apply`) and file reads (`cat .engramory/config.toml`) run directly on the host and return up to 8 KiB in `stdout`.
  - **Blocked commands falsely return `status="ok"` (exit `0`):** `parse_markdown_document` (`docs_tools.py:865-867`) silently drops violating `tier="green"` steps from `parsed.steps`. `smoke_run_green_steps` iterates only `parsed.steps` (never `parsed.diagnostics`), rendering `if safety_issues:` (`docs_tools.py:1444-1455`) unreachable dead code — a runbook containing `rm -rf /` returns `{"status": "ok", "passed": 0, "failed": 0}`.

- **Fix:** Replace `bash -c` + regex denylist with an argv allowlist (`shell=False`, no redirection/interpreters) or route execution through a gVisor (`runsc --network=none`) sandbox per platform standards, and surface `INV-STEP-02` diagnostics as failures in `smoke_run_green_steps`.
